# Chores change log

Newest first. One entry per commit: date, version/build, what changed and why.

- 2026-11-21: 1.0.3 build 7, same pull request (still unmerged; version and build unchanged because this PR has not been built). More chances to ask for an App Store rating, per Brian. 1.0.2 asked once ever behind one shared flag; Apple allows up to three prompts a year.
  - Rating moments, each with its own AsyncStorage key (chores.review.<moment>.v1, value = when it asked) and each at most once ever: checkOff (first chore checked off, unchanged), chart (first printed or shared chart, now separate from checkOff), allDone (first time today's list is fully cleared on a day with at least 3 due, counted like the Today tab), laterDay (first cold launch on a later calendar day than the install day, once 3 or more chores have been completed in total; about 4 s after launch and not while the paywall is up), purchase (after a trial or purchase starts on the paywall, once the app is active again after Apple's confirmation).
  - Shared rules: at most one ask per app launch, never two asks within 3 days (72 hours, newest ask of any moment), never while the Lifetime launch offer is free or the offering is unknown (same rule as Attendance Tracker; in this app the offering's Lifetime price drives the launch offer, promo.json is fallback only). A moment counts as used only when it really asks, so a moment held back by these rules can ask on a later occasion. The old flag chores.reviewAsked.v1 counts as the checkOff ask and is now read only; it has no date, so it starts no 3-day gap.
  - Install day: chores.installDay.v1, written on the first launch of this version (for 1.0.2 users, the day they first open 1.0.3), so laterDay cannot fire on the update day.
  - Files: new src/reviewRules.ts (pure decision, no imports), src/reviews.ts (storage, StoreReview, queue so rapid check-offs are evaluated one after another), src/actions.ts (checkOff + allDone with today's counts), src/screens/Chart.tsx (chart), src/screens/Paywall.tsx (purchase), App.tsx (install day + laterDay). New scripts/check-review-rules.mjs and an npm test script: the repo had no unit checks, so this uses only Node's built-in test runner and the TypeScript already installed, no new dependencies.
  - Behaviour to know: the first check-off ask is unchanged on its own, but the shared rules now apply to it too. Someone who starts a trial on the onboarding paywall is asked there, so their first check-off ask waits until a check-off at least 3 days later. Apple may still show fewer prompts (its own limit is 3 a year per person); a moment that asked counts as used either way.
  - No hidden test section exists in the app, so none was built. Rating prompts do not show in TestFlight builds.
  - Checked: npx tsc --noEmit clean. npm test: 14 checks pass (each moment once, one per launch, 3-day gap, old flag, free mode, allDone and laterDay conditions, a 60-day run firing all five moments spaced 3+ days). Each rule was broken on purpose in a copy and the checks failed every time (7 of 7). A throwaway harness ran src/reviews.ts against stubbed AsyncStorage, StoreReview, AppState and RevenueCat: updater with the old flag, gap, free and unknown offering, rapid check-offs, hasAction false, fresh install, all as expected.
